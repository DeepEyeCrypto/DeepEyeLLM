# Security Policy

## 🔒 DeepEyeLLM Security Principles

DeepEyeLLM is engineered as a **Zero-Trust, Air-Gapped Edge AI Workstation**. We prioritize the absolute privacy of user data, on-device encryption, and memory safety.

---

## 🛡️ Supported Versions

We provide security updates and patches for the following versions:

| Version | Supported |
| :--- | :--- |
| `2.x` (Master Refactor) | ✅ Yes |
| `1.x` | ❌ No |

---

## 🚨 Reporting a Vulnerability

If you discover a security vulnerability or potential threat in DeepEyeLLM:

1. **Do NOT open a public GitHub issue.**
2. Please report your findings directly to the security team via email at:
   - `security@deepeye.network` or contact our maintainers privately on GitHub.
3. Include the following details:
   - Type of vulnerability (e.g., memory corruption in JNI bridge, insecure key storage, prompt injection bypass).
   - Proof of concept (PoC) code or step-by-step reproduction steps.
   - Affected device architectures or Android versions.

---

## ⏱️ Response Timeline

- **Initial Response**: Within 48 hours of report submission.
- **Triage & Verification**: Within 5 business days.
- **Fix & Disclosure**: We aim to release a patch within 14 days and coordinate public disclosure responsibly.

Thank you for helping keep DeepEyeLLM secure and private!
